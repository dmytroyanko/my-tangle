# Project rules

Online store my-tangle.com.ua: Next.js App Router + Payload CMS (Postgres) + Tailwind 4 + shadcn/ui. Node 24 (`nvm use`), pnpm via corepack.

## Architecture: Feature-Sliced Design

Frontend code follows [FSD](https://feature-sliced.design). Layers, top to bottom:

| Layer | Path | What goes there |
|---|---|---|
| app | `src/app/` | Next.js router: route files, layouts, providers, global styles |
| widgets | `src/widgets/` | Large self-contained UI blocks: header, footer, product grid, buy modal |
| features | `src/features/` | User actions: add to cart, checkout, locale switcher, sign in |
| entities | `src/entities/` | Business entities, their data access and display: product, category, order, user |
| shared | `src/shared/` | Business-agnostic code: `ui` (shadcn), `lib` (cn, env, slugify), `i18n`, `config` |

Not part of FSD:
- `src/payload/` is the backend: Payload config, collections, hooks, access, migrations, generated types. Frontend layers read from it only through an entity's `api` segment.
- `src/app/(payload)/` is generated by Payload (admin and REST/GraphQL routes). Do not edit it by hand.
- `src/proxy.ts` and `src/instrumentation.ts` stay at the `src/` root because Next.js requires them there.

Rules (enforced by `steiger` in `pnpm lint`):
- A module imports only from layers below it: `app → widgets → features → entities → shared`.
- Slices on the same layer do not import each other. If two features need the same thing, move it down to an entity or `shared`.
- Import a slice only through its public API, `index.ts` at the slice root (`@/entities/product`), never from its internals. `shared/ui` and `shared/lib` are imported per module (`@/shared/ui/button`).
- Slice segments: `ui` (components), `model` (client state, types, logic), `api` (server data access and server actions), `lib` (helpers), `config`.
- Category pages live at the site root, `/[slug]` (`src/app/(frontend)/[locale]/[slug]/page.tsx`), keeping the current site's flat URLs. Information pages will share this route: resolve a category first, then a page, else 404.
- Product pages are nested under their category: `/[slug]/[product]` (`src/app/(frontend)/[locale]/[slug]/[product]/page.tsx`), one page per series with its colours. `?color=<key>` only preselects a colour; the canonical URL has no parameter. Product slugs are short (`matte`, `mini`) and unique across the site.
- Route files in `src/app/(frontend)/[locale]/` stay thin: read params, call entity `api` functions, compose widgets. Business logic does not live in them.
- Add a slice only when something uses it. Do not create empty layers or placeholder slices.
- Choosing a layer: a user action is a feature; data and how it is shown is an entity; a page section that combines several of them is a widget.

## Server and client code

- Components are Server Components by default. Add `'use client'` only to the smallest component that needs state, effects or browser APIs.
- Read Payload data on the server with the Local API (`getPayload({ config })` from `@payload-config`), inside an entity's `api` segment. Do not call the REST API from the site.
- Pass `locale` to every Payload query. Payload `where` queries match only values stored in that locale, not fallback values: when looking up by slug in `ru`, fall back to the `uk` slug.

## Languages

- Ukrainian (`uk`) is the main language and has no URL prefix. Russian (`ru`) lives under `/ru`. The locale comes only from the URL.
- The list of locales lives in two places that must match: `src/shared/i18n/routing.ts` and `localization` in `src/payload/payload.config.ts`.
- UI strings go in `messages/uk.json` and `messages/ru.json`, with the same keys in both. Do not hardcode user-facing text in components.
- Internal links use `Link` from `@/shared/i18n`, not `next/link`. The admin (`/admin`) is the exception.
- Every page sets `alternates` (canonical and hreflang) with `alternates()` from `@/shared/i18n`, and `<html lang>` matches the locale.
- Payload text that users or search engines see (titles, slugs, descriptions, SEO fields, image alt) is `localized: true`. Prices, variants, SKUs and images are shared across languages.
- Write admin labels and descriptions in Ukrainian.
- Code comments, `README.md`, `AGENTS.md` and other docs are in English. Ukrainian and Russian appear only in UI text (`messages/`), admin labels and content.

## Design tokens

Colors are CSS variables in `src/app/(frontend)/globals.css` (`:root`), used through Tailwind classes. Use the tokens, never raw hex values in components.

| Design name | Value | Tailwind |
|---|---|---|
| primary-text-color | #333333 | `text-foreground` |
| secondary-text-color | #8e8e8e | `text-muted-foreground` |
| light-text-color | #e9e8ee | `text-dark-foreground`, `text-primary-foreground` |
| primary-bg-color | #ffffff | `bg-background` |
| secondary-bg-color | #2a2829 | `bg-dark`, `bg-primary` (buttons) |
| light surface (top bar) | #f8f8f8 | `bg-muted`, `bg-secondary`, `bg-accent` |
| primary-border-color | #e8e7e3 | `border-border` (default for `border`) |
| warm cream surface (promo blocks) | #f4ede4 | `bg-warm`, `text-warm-foreground` |

Typography: Open Sans (latin + cyrillic, `next/font`), body 14px with line-height 1.4. Headings have base sizes: `h1` 30px/700, `h2` 28px/700, `h3` 26px/600, `h4` 22px/600. Use the semantic tag for the outline and override the size with classes only when the design differs.

## Responsive

- Mobile-first: base classes style phones; `sm:`, `md:`, `lg:`, `xl:` add changes for wider screens. Do not write desktop styles and undo them for mobile.
- Breakpoints are Tailwind's defaults, listed in `@theme` in `src/app/(frontend)/globals.css`: `sm` 640px, `md` 768px, `lg` 1024px, `xl` 1280px, `2xl` 1536px. Do not add custom breakpoints or arbitrary media queries (`min-[900px]:`).
- Page content goes in `container`: full width with side padding, capped at 1280px (`--container-site`). Do not add `mx-auto` or `px-*` to it, it already has them.
- Typical layout: product grid 2 columns on phones, 3 from `md`, 4 from `lg` (large series cards with a palette, as in the home category showcase: 2, then 3 from `md`); the header catalog menu sits in one row with the logo from `xl`, a burger menu below.
- Components that appear in containers of different widths (product cards, cart items) adapt to their container with container queries (`@container` on the parent, `@sm:`, `@md:` on children), not to the viewport.
- Check layouts at 360, 390, 430, 768, 1024, 1280, 1440 and 1920px.

## SEO (mandatory)

The main goal of the move: move the site from Webflow to Next.js + Payload with as little SEO loss as possible, then grow the set of search queries the site ranks for and its search potential. Every change is checked against this goal. These rules are mandatory; if a task conflicts with them, stop and tell the user before doing it.

### Keep what already ranks

- Every URL of the current site that is indexed or has backlinks either keeps its exact path on the new site, or gets a **301** to its closest equivalent. No 302, no redirect chains, no mass redirects to the home page, no old URL left as a 404.
- Old URLs end in `.html` (`/kontakty.html`) and are Russian without a prefix: each `/<slug>.html` goes to `/ru/<slug>` with 301 at production cutover. Every changed path is recorded in the "Redirects at cutover" table in `README.md` at the time of the change, not later.
- A published slug (category, product, page) is never changed without adding a 301 from the old one. Slugs are short, Latin, lowercase, without trailing slashes.
- A new page is never weaker than the old one it replaces: title, meta description, H1, text, internal links and image alts are kept or improved. Ranking text is not removed; moving it lower on the page is fine, as long as it stays in the HTML.
- Before cutover: crawl the old site (sitemap and links) and compare it with the new one page by page: status, title, description, H1, canonical, main text. Differences are fixed or agreed with the user.

### Every page

- Content is rendered on the server and is in the initial HTML. Nothing that should rank appears only after JavaScript runs. Collapsible text uses native `<details>`.
- A unique `<title>` and meta description per page and language (an editor's SEO fields first, a template from messages as the fallback). Exactly one `h1`; headings go down without skipping levels (an `sr-only` heading is fine where the design has none).
- Every page sets `alternates()` from `@/shared/i18n`: a self canonical without query parameters, and reciprocal hreflang `uk`, `ru`, `x-default`. `<html lang>` matches the locale.
- A missing page returns a real 404 status (`notFound()`), never a 200 with an error text. Layouts do not set a canonical (it would leak to 404 pages).
- Query parameters that only filter or preselect (`?color=`, `?series=`) never create new indexable pages: their canonical is the clean URL. Cart, checkout, account, search and `/admin` are `noindex` and stay out of the sitemap.
- Before cutover the site must have `sitemap.xml` (only canonical, indexable 200 URLs, both languages, with hreflang) and `robots.txt` that points to it.

### Structured data

- Schema.org JSON-LD is rendered with `JsonLd` from `@/shared/ui/json-ld`, built with helpers from `@/shared/lib/structured-data`; absolute URLs use `siteUrl` from `@/shared/config`. Home: `OnlineStore` and `WebSite` (`storeJsonLd()`); every inner page: `BreadcrumbList`; product pages: `Product` with `Offer`/`AggregateOffer` and characteristics; FAQ blocks may add `FAQPage`.
- Structured data repeats only what is visible on the page. No made-up ratings, reviews, prices or availability.

### Speed

- Core Web Vitals are part of SEO. The LCP image (hero, first product photos) loads with `loading="eager"` and `fetchPriority="high"`; every image goes through `next/image` with correct `sizes` and fixed dimensions or aspect ratio (no layout shift). Fonts only through `next/font`. No heavy client JavaScript where a Server Component will do.

### Links and images

- Internal links use `Link` from `@/shared/i18n`. Every indexable page is reachable through links (menu, breadcrumbs, category → product, related items); no orphan pages.
- Links to other websites get `rel="nofollow noopener noreferrer"` and `target="_blank"`: we do not pass link weight or the referrer to external sites. Use `externalLinkProps` from `@/shared/lib/links`; Payload rich text rendered with `RichText` from `@/shared/ui/rich-text` adds them automatically. `mailto:` and `tel:` links are not external sites.
- Every content image (products, banners, photos) has a meaningful, localized alt and a meaningful file name. A purely decorative image whose meaning is already given by text next to it (e.g. a menu icon beside its label) gets `alt=""`, so screen readers do not read the same text twice.

### Growing the search reach

- One search intent per URL. Before adding a page, check that no existing page already targets that intent (no cannibalization); extend the existing page instead.
- New pages (series, categories, guides like "how to tell an original", "how to clean") target a concrete group of queries and are linked from related pages.
- Texts are written for people, in natural Ukrainian and Russian, and are factual: product facts come from the manufacturer or the user. No invented characteristics, dimensions or claims; product, colour and series names are not changed without the user's request.

### Process

- Changes that affect SEO (URLs and slugs, titles and descriptions templates, canonical, robots/noindex, redirects, removing or moving content off a page) are named in the report to the user; risky ones are agreed before doing them.
- After changing a page, check: status code, title, description, canonical, hreflang, one `h1` and the heading outline, valid JSON-LD, no horizontal scroll on mobile.
- After cutover: verify the site in Google Search Console, submit the sitemap, monitor 404s and index coverage, and keep the redirects permanently.

## Payload

- See the Payload skill in `.claude/skills/payload/` for API reference.
- After changing collections: `pnpm generate:types`; `pnpm generate:importmap` if admin components were added.
- Dev uses schema push. Schema changes for production are migrations: `pnpm payload migrate:create <name>`, committed in `src/payload/migrations/`. Production applies them on startup.
- Required env vars are read with `requireEnv()` from `@/shared/lib/env`.
- Seed scripts live in `src/payload/seed/` (data as JSON next to the script) and run with `pnpm payload run <file>`. They must be safe to re-run: match existing documents by slug and media by file name.
- Product photos come only from the manufacturer (tangleteezer.com and its regional stores, `cdn.shopify.com`). Search there first, including older product images under other names (Pearlescent Matte is the manufacturer's "Matte Ombre"). Only when the manufacturer has no photo of a colour may the current site's or the supplier's photos stay, as a temporary exception the user agreed to: Compact Styler Rose Gold Black and Pink Matte Chrome, the first photo of Compact Styler Rose Gold Ivory (a Sephora packshot the user chose, as the manufacturer only shows it with the box), The Original Mini Marine Splash, The Ultimate Detangler Vanilla Latte, Invisibobble designs no longer on invisibobble.com (17, listed in the seed by their cdn.prod.website-files.com URLs), The Scalp Exfoliator Seafoam Blue (krasota.shop photos the user chose; it is not the manufacturer's Mint Green Whisper, a different colour).
- Product swatch colours are `variants[].color` (#rrggbb); card labels are `series` and `tags`. A product whose variants have no colour (a spray) shows no palette.
- Prices: the admin enters `fullPrice` (brushes and sprays: the supplier's full price minus 1 UAH; Invisibobble: the supplier's full price as is; a variant may override it). `price` is never typed in: `computeSalePrices` (`src/payload/hooks/salePrices.ts`) sets it to the full price minus the discount: the colour's `discountPercent`, else the product's, else the Shop settings global (20% by default), rounded to whole UAH. Brushes and sprays use the global 20%. Invisibobble products have 0 (the site price is the supplier's recommended price) and a colour discount only where the supplier discounts that design, matching the supplier's sale price. Changing the global discount reprices every product. Cards and product pages show the site price with the full price crossed out and the discount (`ProductPrice`).
- Out of stock (`variants[].inStock` off): the colour stays visible with a struck-through swatch; on cards the photo (greyed), title and price are muted, and "Немає в наявності" text replaces the buy button on cards and the product page; a product opens on its first colour in stock; a product with no colour in stock keeps its page (200, `OutOfStock` in JSON-LD) and goes to the end of category and home lists. A product gone for good gets a 301 to its category or a similar product, never a 404. No "notify me" button for now; stock sync from the supplier's feed comes in a later stage.
- Each category has a `brand` (`src/shared/config/brands.ts`: Tangle Teezer or Invisibobble). It sets the brand and brand country in the characteristics, the brand in Product JSON-LD and the product meta title (`withBrand`: product titles that already start with the brand, like "Invisibobble Clipstar", are not prefixed again). Never hardcode "Tangle Teezer" for products.
- The home page shows the categories with `showOnHome`, in `order`. Do not hardcode category slugs in pages.
- Product slugs are unique across all categories (`mini` is taken by The Ultimate Detangler Mini). The seed sets `generateSlug: false`, otherwise Payload makes the Russian slug from the title.
- Media that nothing uses is deleted, not kept: after replacing photos or removing products, run `src/payload/seed/cleanup-media.ts` (lists unused files; `CLEANUP_APPLY=1` deletes them). Show the list to the user before deleting; on production, delete only with their explicit confirmation. Arguments like `--dry-run` do not reach `payload run`, so options are passed as env vars.
