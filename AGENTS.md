# Project rules

Online store my-tangle.com.ua: Next.js App Router + Payload CMS (Postgres) + Tailwind 4 + shadcn/ui. Node 24 (`nvm use`), pnpm via corepack.

## Architecture: Feature-Sliced Design

Frontend code follows [FSD](https://feature-sliced.design). Layers, top to bottom:

| Layer | Path | What goes there |
|---|---|---|
| app | `src/app/` | Next.js router: route files, layouts, providers, global styles |
| widgets | `src/widgets/` | Large self-contained UI blocks: header, footer, product grid, buy modal |
| features | `src/features/` | User actions: add to cart, checkout, locale switcher, sign in |
| entities | `src/entities/` | Business entities, their data access and display: product, category, order, user |
| shared | `src/shared/` | Business-agnostic code: `ui` (shadcn), `lib` (cn, env, slugify), `i18n`, `config` |

Not part of FSD:
- `src/payload/` is the backend: Payload config, collections, hooks, access, migrations, generated types. Frontend layers read from it only through an entity's `api` segment.
- `src/app/(payload)/` is generated by Payload (admin and REST/GraphQL routes). Do not edit it by hand.
- `src/proxy.ts` and `src/instrumentation.ts` stay at the `src/` root because Next.js requires them there.

Rules (enforced by `steiger` in `pnpm lint`):
- A module imports only from layers below it: `app → widgets → features → entities → shared`.
- Slices on the same layer do not import each other. If two features need the same thing, move it down to an entity or `shared`.
- Import a slice only through its public API, `index.ts` at the slice root (`@/entities/product`), never from its internals. `shared/ui` and `shared/lib` are imported per module (`@/shared/ui/button`).
- Slice segments: `ui` (components), `model` (client state, types, logic), `api` (server data access and server actions), `lib` (helpers), `config`.
- Route files in `src/app/(frontend)/[locale]/` stay thin: read params, call entity `api` functions, compose widgets. Business logic does not live in them.
- Add a slice only when something uses it. Do not create empty layers or placeholder slices.
- Choosing a layer: a user action is a feature; data and how it is shown is an entity; a page section that combines several of them is a widget.

## Server and client code

- Components are Server Components by default. Add `'use client'` only to the smallest component that needs state, effects or browser APIs.
- Read Payload data on the server with the Local API (`getPayload({ config })` from `@payload-config`), inside an entity's `api` segment. Do not call the REST API from the site.
- Pass `locale` to every Payload query. Payload `where` queries match only values stored in that locale, not fallback values: when looking up by slug in `ru`, fall back to the `uk` slug.

## Languages

- Ukrainian (`uk`) is the main language and has no URL prefix. Russian (`ru`) lives under `/ru`. The locale comes only from the URL.
- The list of locales lives in two places that must match: `src/shared/i18n/routing.ts` and `localization` in `src/payload/payload.config.ts`.
- UI strings go in `messages/uk.json` and `messages/ru.json`, with the same keys in both. Do not hardcode user-facing text in components.
- Internal links use `Link` from `@/shared/i18n`, not `next/link`. The admin (`/admin`) is the exception.
- Every page sets `alternates` (canonical and hreflang) with `alternates()` from `@/shared/i18n`, and `<html lang>` matches the locale.
- Payload text that users or search engines see (titles, slugs, descriptions, SEO fields, image alt) is `localized: true`. Prices, variants, SKUs and images are shared across languages.
- Write admin labels and descriptions in Ukrainian.

## Design tokens

Colors are CSS variables in `src/app/(frontend)/globals.css` (`:root`), used through Tailwind classes. Use the tokens, never raw hex values in components.

| Design name | Value | Tailwind |
|---|---|---|
| primary-text-color | #333333 | `text-foreground` |
| secondary-text-color | #8e8e8e | `text-muted-foreground` |
| light-text-color | #e9e8ee | `text-dark-foreground`, `text-primary-foreground` |
| primary-bg-color | #ffffff | `bg-background` |
| secondary-bg-color | #2a2829 | `bg-dark`, `bg-primary` (buttons) |
| light surface (top bar) | #f8f8f8 | `bg-muted`, `bg-secondary`, `bg-accent` |
| primary-border-color | #e8e7e3 | `border-border` (default for `border`) |
| warm cream surface (promo blocks) | #f4ede4 | `bg-warm`, `text-warm-foreground` |

Typography: Open Sans (latin + cyrillic, `next/font`), body 14px with line-height 1.4. Headings have base sizes: `h1` 30px/700, `h2` 28px/700, `h3` 26px/600, `h4` 22px/600. Use the semantic tag for the outline and override the size with classes only when the design differs.

## Responsive

- Mobile-first: base classes style phones; `sm:`, `md:`, `lg:`, `xl:` add changes for wider screens. Do not write desktop styles and undo them for mobile.
- Breakpoints are Tailwind's defaults, listed in `@theme` in `src/app/(frontend)/globals.css`: `sm` 640px, `md` 768px, `lg` 1024px, `xl` 1280px, `2xl` 1536px. Do not add custom breakpoints or arbitrary media queries (`min-[900px]:`).
- Page content goes in `container`: full width with side padding, capped at 1280px (`--container-site`). Do not add `mx-auto` or `px-*` to it, it already has them.
- Typical layout: product grid 2 columns on phones, 3 from `md`, 4 from `lg`; the header catalog menu sits in one row with the logo from `xl`, a burger menu below.
- Components that appear in containers of different widths (product cards, cart items) adapt to their container with container queries (`@container` on the parent, `@sm:`, `@md:` on children), not to the viewport.
- Check layouts at 360, 390, 430, 768, 1024, 1280, 1440 and 1920px.

## SEO

- Existing URLs and SEO of the current Webflow site must survive the move. Redirects from the old Russian URLs to `/ru/...` are set up at production cutover.
- Structured data (schema.org JSON-LD) is rendered with `JsonLd` from `@/shared/ui/json-ld`. The home page has the store (`OnlineStore`) and `WebSite` from `storeJsonLd()` in `@/shared/lib/structured-data`; absolute URLs use `siteUrl` from `@/shared/config`.
- Every content image (products, banners, photos) has a meaningful, localized alt. A purely decorative image whose meaning is already given by text next to it (e.g. a menu icon beside its label) gets `alt=""`, so screen readers do not read the same text twice.

## Payload

- See the Payload skill in `.claude/skills/payload/` for API reference.
- After changing collections: `pnpm generate:types`; `pnpm generate:importmap` if admin components were added.
- Dev uses schema push. Schema changes for production are migrations: `pnpm payload migrate:create <name>`, committed in `src/payload/migrations/`. Production applies them on startup.
- Required env vars are read with `requireEnv()` from `@/shared/lib/env`.

## UI

- Add shadcn components with `pnpm dlx shadcn@latest add <name>`; they land in `src/shared/ui/`.
- Use `cn` from `@/shared/lib/utils` for class names.

## Checks before finishing

`pnpm lint` (ESLint + steiger) and `npx tsc --noEmit` must pass.
