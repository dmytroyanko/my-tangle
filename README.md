# my-tangle

Online store [my-tangle.com.ua](https://my-tangle.com.ua): Next.js (App Router) + Payload CMS + Tailwind CSS + shadcn/ui, Postgres database.

## Local setup

Requires Node 24 (see `.nvmrc`), corepack and Docker.

```bash
nvm use
corepack enable pnpm          # the pnpm version from package.json
cp .env.example .env          # and set PAYLOAD_SECRET: openssl rand -hex 32
docker compose up -d          # Postgres on port 5433
pnpm install
pnpm dev
```

- Site: http://localhost:3000
- Admin: http://localhost:3000/admin (the first visit creates the admin user)

## Structure

The frontend follows [Feature-Sliced Design](https://feature-sliced.design). The full rules for developers and AI agents are in `AGENTS.md`.

- `src/app` — Next.js router: `(frontend)/[locale]` is the site, `(payload)` the admin and API (generated by Payload)
- `src/widgets`, `src/features`, `src/entities` — FSD layers
- `src/shared` — shared code: `ui` (shadcn/ui, `pnpm dlx shadcn@latest add <name>`), `lib`, `i18n`, `config`
- `src/payload` — backend: Payload config, collections, globals, hooks, migrations, generated types
- `messages/` — UI text for each language

After changing collections: `pnpm generate:types` (and `pnpm generate:importmap` if custom admin components were added).

`pnpm lint` runs ESLint and `steiger`, which checks the FSD rules (imports only from lower layers, through a slice's public API).

## Languages

The site is bilingual: Ukrainian is the main language, Russian the second one.

- URLs: Ukrainian without a prefix (`/`, `/the-ultimate-detangler`), Russian under `/ru` (`/ru`, `/ru/the-ultimate-detangler`). `/uk/...` redirects to the address without a prefix. The language comes only from the URL; there is no redirect by browser language.
- UI text (buttons, labels): `messages/uk.json` and `messages/ru.json`, with the same keys in both files.
- Content in the admin: the language switcher at the top of a document. Titles, slugs, descriptions, SEO fields and photo alt texts are filled in per language; prices, variants and photos are shared. Without a Russian translation the Ukrainian text is shown.
- Slugs are generated from the title by transliteration: Ukrainian by the official standard (Cabinet of Ministers resolution No. 55), Russian by common web transliteration.
- Every page outputs `canonical` and `hreflang` (uk, ru, x-default) through `alternates()` from `src/shared/i18n/alternates.ts`. The site address for these links is the `SITE_URL` variable.
- The list of languages lives in two places: `src/shared/i18n/routing.ts` and `localization` in `src/payload/payload.config.ts`.

## Prices

The admin enters only the **full price** of a product: for brushes and sprays the supplier's full price minus 1 UAH, for Invisibobble the supplier's full price as is. A colour whose full price differs from the product's has its own full price.

The site price is calculated by Payload on every save: the full price minus the discount, rounded to a whole hryvnia. The discount is set in **Shop settings** in the admin (20% by default); saving a new value reprices every product. A product can have its own discount (the "Знижка, %" field, 0 for none), which then takes priority over the shop one, and a colour can have its own on top of that. Invisibobble products have 0, with a colour discount only where the supplier discounts that design.

The site shows the site price with the full price crossed out and the discount next to it. The calculation is in `src/payload/hooks/salePrices.ts`.

## Home page

The home page shows a block for every category with **"Показувати на головній"** checked in the admin, in the order of the category's "Порядок" field (the same order as the menu).

## Database migrations

Locally (`pnpm dev`) Payload updates the schema by itself. For production, schema changes are recorded as migrations:

```bash
pnpm payload migrate:create <name>   # after changing collections; commit src/payload/migrations
```

The production server applies new migrations automatically on startup (`prodMigrations`).

### Local database: `pnpm dev` does not respond

If `pnpm dev` started after a collection change (or a branch switch) but the site, admin and API do not respond, Payload is waiting for an answer in the terminal running `pnpm dev`. It is fitting the local database schema to the collections and asks how to change the tables, for example:

```
Is snapshot column in _pages_v table created or renamed from another column?
❯ + snapshot   create column
```

No page is served until it gets an answer. Two ways out:

- **Answer in the terminal.** For new fields choose `+ ... create column` (Enter on the first option); for a data loss question, `y`. Choose a rename (`~ ... rename column`) only when a field really was renamed, to keep its data. Never choose an option that truncates a table: it deletes every row. A new required field on a table with rows can trigger that question; give the field a `validate` function instead of `required` so the column can be empty.
- **Recreate the local database** if it holds nothing you need:

  ```bash
  # stop pnpm dev (Ctrl+C), then:
  docker compose down -v && docker compose up -d
  pnpm dev
  ```

  `docker compose down` stops and removes the Postgres container, and `-v` also removes the volumes from `docker-compose.yml`: `pgdata`, i.e. all local database data (users, products, pages), and `media` if you ran `docker compose --profile app`. `docker compose up -d` creates an empty database; Payload fills in the schema on the first `pnpm dev`, and the admin user has to be created again at http://localhost:3000/admin. This does not touch production, R2 or the `media/` folder in the project (where `pnpm dev` stores photos).

### Catalog import

Categories with their series, colours and photos are loaded into the database by a script. Each category is a separate file in `src/payload/seed/catalog/` (`ultimate-detangler.json`, `the-complete-carebrush.json`, `the-original-children-mini.json`, `compact-styler.json`, `easy-dry-go.json`, `the-ultimate.json`, `back-combing-hairbrush.json`, `the-scalp-exfoliator-and-massager.json`, `pet-teezer.json`, `rezinki-invisibobble.json`): names and series from the current site (Pet Teezer, a new category: stock from the supplier, names and texts from the manufacturer), full prices from the supplier, photos only from the manufacturer's site (a few colours it never photographed keep the current site's photos for now, see `AGENTS.md`).

```bash
pnpm payload run src/payload/seed/catalog.ts                                  # every category
CATEGORY=the-complete-carebrush pnpm payload run src/payload/seed/catalog.ts  # one category
```

The script downloads the photos, compresses them to WebP (up to 1600px) and stores them in Payload media. Running it again is safe: it only adds what is missing and leaves categories and products already in the database alone (they are edited in the admin). To overwrite them with the JSON data, run it with `SEED_UPDATE=1`:

```bash
SEED_UPDATE=1 CATEGORY=the-complete-carebrush pnpm payload run src/payload/seed/catalog.ts
```

Photos are not duplicated: the script finds already uploaded ones by file name.

### Information pages

Articles and other information pages are imported the same way, one JSON file per page in `src/payload/seed/pages/`. Texts follow the manufacturer's, adapted for the shop. Each language has its own slug: Ukrainian by transliteration (`/yak-myty-tangle-teezer`, `/yak-vidriznyty-oryhinal`), Russian the old site's (`/ru/kak-myt-tangle-teezer`, `/ru/kak-otlichit-original`). A page opened by the other language's slug redirects to its own. A page can also have questions and answers grouped by topic (the FAQ, `/chasti-pytannia`), rendered with `FAQPage` structured data. They live at the site root next to categories: `/[slug]` shows a category if one has that slug, otherwise the page.

```bash
pnpm payload run src/payload/seed/pages.ts                            # every page
PAGE=kak-myt-tangle-teezer pnpm payload run src/payload/seed/pages.ts  # one page
```

Animated GIFs are stored as animated WebP, at most 640px wide (about 300 KB).

### Unused media

After replacing photos or removing products, old files stay in media. The script lists the files that no product, category or page uses (both languages, drafts included), and with `CLEANUP_APPLY=1` deletes them. Deletion cannot be undone, so review the list first:

```bash
pnpm payload run src/payload/seed/cleanup-media.ts
CLEANUP_APPLY=1 pnpm payload run src/payload/seed/cleanup-media.ts
```

## Redirects at cutover

The old Webflow site's URLs end in `.html` (`/kontakty.html`); without `.html` they return 404. At cutover every old (Russian) URL `/<slug>.html` is redirected with 301 to `/ru/<slug>`. URLs whose slug itself changed:

| Old URL | New URL |
|---|---|
| `/the-wet-detangler.html` | `/ru/the-ultimate-detangler` |

## Docker (production)

```bash
docker compose --profile app up --build   # app + Postgres, http://localhost:3000
```

Required variables: `PAYLOAD_SECRET`, `DATABASE_URL`. Without them the container exits with an error right at startup.

## Product photos

- If `S3_BUCKET` (+ `S3_ENDPOINT`, keys) is set, files are stored in Cloudflare R2 or another S3-compatible storage.
- Otherwise on disk in `MEDIA_DIR` (`/app/media` in the container, the `media` volume in docker-compose).
